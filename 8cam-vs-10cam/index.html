8-cam vs 10-cam

4D Gaussian Splatting novel-view synthesis — fork_flip_egg

The same dynamic scene reconstructed twice: once from the standard 8-camera rig, once from a 10-camera rig adding two extra viewpoints. Both runs use the identical pipeline and the same trial, so the only variable is how many input views the reconstruction had. Drag the seam in each slider to wipe between them — left is 8-cam, right is 10-cam.

Read the sliders as a side-by-side, not a pixel-aligned A/B. The novel-view path is generated from the input rig, so the 10-camera run does not fly exactly the same path as the 8-camera one — the two clips measure 18.4 dB PSNR against each other, where the same path re-rendered with different post-processing measures 33 dB and two entirely different scenes measure 14.5 dB. The paths coincide at some moments and drift apart at others. Both clips are time-aligned to the same scene frames, so the action stays in step.

Restricted to cameras 1–8, which both runs share, so the two columns describe the same views. Read this one with care: it measures how well each reconstruction reproduces its own input views, not how good the novel views are. The 10-cam run has two more views to satisfy with the same capacity, so some drop here is expected and is not on its own evidence of a worse result. On the two extra cameras that only the 10-cam run sees, it scores PSNR 24.65 / SSIM 0.914 / LPIPS 0.105 raw and 24.08 / 0.877 / 0.109 after Difix3D — well below its own average, so the added viewpoints are also the hardest ones to fit.

Verdict — no measured gain from the two extra cameras. The 10-cam run trails the 8-cam run on all six no-reference measures of the rendered clip, both before and after enhancement. The Difix3D pass, by contrast, helps both runs by a wide margin (MUSIQ 51.7 → 61.8 for 8-cam, 45.1 → 60.2 for 10-cam) and narrows but does not close the gap.

Two reasons to hold this loosely: the two runs fly different novel-view paths, so part of the difference may be that the 10-cam path visits harder viewpoints rather than that the reconstruction is worse; and this is one scene and one trial. It is evidence that the extra pair of cameras did not pay off here, not that a wider rig cannot help in general.

Both clips render at 1440×406, 24 fps, trimmed to 9.33 s — the length of the shorter run — and cover the same scene frames, so the action stays in step as you wipe. Slider adapted from Ref-NeRF's video_comparison.js, generalised to N panes.
